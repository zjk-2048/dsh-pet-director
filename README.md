# dsh-pet-director · 大肥鱼小导演

> 让 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的桌宠把「说的话」变成「真的动作」。
> An out-of-tree director for the DSH desktop pet: it listens to pet-chat memory and turns spoken commands into real animation cues via the pet's public API.

**不改 `dsh-pet` 的一行代码**，不注入、不挂钩、不打包进插件——只是一个旁听对话、调用公开接口的小进程。删掉文件夹就干净卸载。

---

## 它解决什么问题

桌宠能聊天，但聊天和动作是两条互不相通的管线：

```
/chat → LLM → 一句回复 → 气泡（只有嘴动）
右键菜单 / /anim → 动作（只有身体动）
```

于是你说「往左跑两步」「转个圈」「拉个小提琴」，它只会回你一句「好呀～」，然后站着不动。

**大肥鱼小导演**就是补上中间那层：读它自己写的对话记忆，判断这句话是什么意思，再调用插件公开的点播接口让它真的做出来。

## 工作原理

```
你（或别人）在桌宠聊天框说话
        │
        ▼
dsh-pet 把这一问一答写进 $DSH_HOME/dsh-pet/memory.json
        │
        ▼
director.mjs 每 700ms 读一次，发现新的一对
        │
        ▼
规则判定意图（方向 > 动作关键词 > 情绪兜底）
        │
        ├─ 动作：POST /dsh-pet-7340/anim?pet=main&surface=any   body {name, facing?}
        └─ 位移：POST /dsh-pet-7340/position?pet=main&surface=any  body {x, y, mode:'line', duration}
        │
        ▼
桌宠真的走 / 转圈 / 拉琴 / 吃饭 / 斜着挪……（网页与桌面两端同时）
```

只用到 dsh-pet 面向第三方插件公开的两个端点（`/anim`、`/position`），名字全部走插件自己的动画白名单，**不发生任何文件改动**。

## 特性

- **89 个动作**全覆盖：点击回应 5、转向/移动 4、小动作 18、玩耍 27、吃什么 12、时节 21、文字类 2
- **313 条触发规则**：动作名本身、去前缀的核心词、口语化别名（「来段舞」→ 可爱宅舞、「来份大闸蟹」→ 吃大闸蟹）
- **二维移动**：斜向 / 纵向走 `/position` 滑行，复用现有移动动画（螃蟹走路、漂浮踏步），带可调的前摇与时长
- **余额可知**：把当前余额写进人设，问它「还有多少钱」会直接报数字，而不是「我看不到」
- **零依赖**：单个 `.mjs` 文件，Node 22+，不用 `npm install`
- **零侵入**：不修改、不替换、不重打包 dsh-pet；插件升级不受影响
- **自动重连**：DSH 重启换端口后自动重新探测（从 `netstat` 找监听端口再逐个探测）
- **可调参数即时生效**：`settings.json` 每次移动前重读，改完不用重启
- **离线可测**：`--test` 单条判定、`--selftest` 全量规则自检，都不花钱、不动宠物

## 快速开始

前置：已经装好 `dsh-pet`，宠物配了 `display: both`（或 `desktop`）。

```bash
# 1. 启动（Windows 双击 start.cmd 也行）
node director.mjs

# 2. 看到这行就说明连上了
# [director 15:02:35] 连上 DSH：127.0.0.1:59400

# 3. 去桌宠聊天框说：往左上、转个圈、吃个西瓜、拉个小提琴……
```

停止：`Ctrl+C`，或 Windows 双击 `stop.cmd`。

### 命令行参数

| 参数 | 说明 |
|---|---|
| `--port <端口>` | 指定 DSH 端口（默认自动探测） |
| `--pet <id>` | 操作哪只宠物（默认 `main`） |
| `--memory <路径>` | 对话记忆文件（默认 `$DSH_HOME/dsh-pet/memory.json`） |
| `--dry` | 常驻但只打印判定，不发动作 |
| `--test "一句话"` | 离线测一条判定，不聊天、不发请求 |
| `--selftest` | 全量自检：313 条规则逐条验证 |

## 让它「知道」你的余额

问它「我还有多少余额」时，它会直接报出真实数字，而不是「我够不着你的账户哦」。

做法**不改插件**：导演每分钟读一次 `/state` 里的余额（与插件自己显示的完全同源），把这一行字符串拼进宠物的 `whisperPrompt`（人设）。宿主每次对话都会重读配置、把人设放进 system prompt，于是模型在生成回复时就已经知道这个数字了。

```
你：我还有多少余额？
它：还剩三块三毛一呢，省着点花呀～
```

注意：

- 余额数字的**新鲜度跟插件自己的刷新一致**（插件每 30 分钟刷一次，或你点「查看余额」时刷新）。
- 导演会重写 `~/.dsh/dsh-pet/main-config.jsonc` 里那只宠物的 `whisperPrompt`——**写成普通 JSON，会丢掉文件里的注释**。想关掉：`settings.json` 里 `"balancePersona": false`。
- 注入块以 `【当前余额】` 开头，每次覆盖前会先剥掉旧块，不会越堆越长。

## 配置

`settings.json`（每次移动前重读，改完直接再说一句即可）：

```json
{
  "glideMs": 8000,        // 位移本身的时长（毫秒）：越大越慢
  "leadMs": 300,          // 前摇：动画起播后先等这么久再开始位移
  "stepX": 0.15,          // 每次横向挪多远（屏幕宽度比例）
  "stepY": 0.12,          // 每次纵向挪多远（屏幕高度比例）
  "balancePersona": true, // 是否把余额写进人设（让模型知道）
  "balanceSyncMs": 60000  // 余额同步间隔（毫秒）
}
```

调参口诀：

- 人还没动、位置先走了 → `leadMs` 加大
- 动作做完了人还在挪 → `glideMs` 加大
- 人到了还在原地走 → `glideMs` 减小

## 怎么加新说法

编辑 `director.mjs` 的 `CATALOG`：

```js
'吃西瓜': ['西瓜', '吃瓜'],   // 动画名（必须与配置里的名字逐字一致）→ 别名
```

改完跑一次自检，确认没有和别的规则抢：

```bash
node director.mjs --selftest
```

## 已知限制

1. **一条消息只做一个动作**：「跑一段然后转圈」只会执行前半句。
2. **判定是规则，不是模型**：零成本、零延迟、可预测，但没写进关键词的说法不会动。模型判定需要打包成 DSH 插件才能复用宿主 `ctx.llm`，见路线图。
3. **移动距离不可精确指定**：横向走路是插件内部的随机区间；斜/竖向是固定步长。
4. **斜向/纵向是滑行，不是走**：宠物素材没有上下/斜向的位移动画。真正的斜走需要改渲染层运动学。
5. **网页端与桌面端共享动作**：因为写的是同一份状态叶子，两端同时播；无法只让桌面端动。
6. 只支持 Windows 的自动端口探测（用 `netstat`）；其它平台请用 `--port`。

## 路线图

- [ ] 一条消息串多个动作（「跑一段然后转圈」）
- [ ] 模型判定（打包成 DSH 插件，复用 `ctx.llm`，规则作为兜底）
- [ ] 鼠标长时间停留后自动凑近（需要改桌面 helper，用 `screen.getCursorScreenPoint()`）
- [ ] 真·斜向走路（渲染层把 1D 走路扩成 2D 方向向量）
- [ ] 跨平台端口探测

## 与 dsh-pet 的关系

- 只读 `memory.json` 与 `/config`、`/state`，只调用 `/anim`、`/position` 两个动作端点；
- **唯一的写操作**：开启 `balancePersona` 时改写 `~/.dsh/dsh-pet/main-config.jsonc` 里那只宠物的 `whisperPrompt`（为了把余额带进 system prompt）。关掉即完全不写；
- 不修改插件文件（`lib/`、`runtime/` 一律不碰）、不注入客户端代码、不依赖插件内部实现；
- 插件升级/重装不会破坏本工具；本工具出问题也不会影响宠物本身。
